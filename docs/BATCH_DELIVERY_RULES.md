## 3. Visual and animation rules
- Visualize political disputes, appointments, social crises, family/authority, diplomacy, logistics, succession and war, not only battles. Illustrations explain the exact beat; relationship diagrams have labeled semantics, sequences show only documented order, comparisons label [Chính sử]/[Tiểu thuyết] etc. Do not imply direction, causal certainty, troop counts or formations from decorative shapes.
- Keep existing 16 historical scene images and existing shared portraits unless PO explicitly asks for a change. DEC-UX-034 clarification: no additional historical art, museum photos or historical image assets by default. Use curated locally stored symbolic SVG and editorial illustrations/diagrams; no AI art or new image service without explicit PO authorization. If a new character has no authorized portrait, use the consistent readable name/Hán fallback. If PO authorizes new historical imagery later, prioritize 三國志圖像 with exact provenance and file checks; never treat artwork as evidence.
- Lucide = functional interface. Game-icons = contextual symbol assets; preserve source, author, license and modifications, deduplicate and check actual file/rendering. No medieval European visual clichés for period-specific scenes. New icon only when it improves comprehension. Use existing Ink & Silk colors and layout, existing Motion/Rough Notation, not new UI libraries unless authorized.
- Every episode has an authored visual plan and motion metadata. Empty decision/reveal/circle/underline arrays or absent optional reveal only when reviewed and justified; no arbitrary stamps or animated spoilers. Verify actual render anchors, not only that an entry exists in a file. Preserve text visibility if animation disabled. A new diagram must fit at 320px without horizontal scrolling and keep text readable.
- No fixed 22-diagram / 16-scene / 23-profile / 39-snapshot / 9-quote / 6-event quotas for future content. Those are v6 baseline counts for regression, not limits. Keep previous valid records; grow as required by each batch. Do not force meaningless duplicate illustrations, quotes, journey lines or snapshots to meet a number.

## 4. Work packages and ownership
1. Research: identify episodes, sources, timeline, people/roles/quotes, six-axis evidence, important places and conflicts, setup/payoffs; mark uncertainty and literature layers.
2. Storytelling: complete all authorized prose, update ledger; identify visual/motion anchors, quote and character/Atlas data needs for handoff. Follow existing scope of “kể tiếp” — do not independently code or deploy.
3. Visual research/integration: map and render meaningful visuals across EVERY episode, reuse existing asset registry, curate approved icons, update storyBeats. Verify precise anchors and file identity.
4. Wiki/Atlas integration: fill all affected identities, six-axis timeline, quotes where sourced, links, event/geography/relations/journey and focus/date controls. Review both new and existing affected people/events. Reuse existing components.
5. QA and release: integrate batch, validate all surfaces plus prior content, review screenshots, confirm exact SHA and receive PO release approval. No second public site. These are responsibilities within existing packages, not extra mandatory chats or new frameworks.

## 5. Definition of Done — one coverage matrix in Latest Handoff
For each new episode list Reader prose/sources, visual IDs + art disposition, motion anchors, referenced people and Wiki profile/metrics/quote disposition, Atlas event IDs/year/place/precision, graph/route disposition and navigation/search status. For each new or materially changed person list stable ID, profile, portrait/fallback, six-axis snapshots (including unchanged-axis reasons), quotes found or researched-none, episode backlinks and Atlas roles/relations. Store detailed mapping in existing batch evidence/visual deliverables; handoff stays short and references it. Do not create redundant ledgers.

Use PASS / FAIL / BLOCKED / NOT TESTED per applicable check. N/A only with explicit reason for optional or unsupported material (e.g., no sourced quote, no documented journey or no important decision). Missing mandatory element is FAIL/BLOCKED, not N/A. A stage handoff may be incomplete; an entire batch is not ready for release until mandatory checks pass and optional absence is explained. No invented evidence to satisfy a UI slot. No silent omissions.
